Evaluation

Brick & Mortar AI 2025

Fixing the evaluation of a few-shot barcode classifier

I fine-tuned a ResNet-12 prototypical-network classifier on damaged and glared barcode images, then found the reported numbers were an artefact of the harness. There was split leakage, a 1-shot vs 3–40-shot support mismatch, and a 3-way vs 11-way evaluation mismatch. I rebuilt the held-out split and the episode sampler. Under the corrected 11-way protocol the model reached 89.7% validation accuracy, against the 46.7% that had been reported.

PyTorch · ResNet-12 · prototypical networks · episodic evaluation

Open source

Personal project 2026

Vision Inference Pipeline

A standalone computer-vision inference framework built around the same runner, backend and stream boundaries used in larger streaming systems. It runs prototypical few-shot classification with PyTorch locally or over Triton gRPC, with tests checking numerical parity between the two backends. Support prototypes are cached when the backend starts, and a benchmark checks the measured speedup against the expected cost model.

I also evaluated it on Omniglot with 100 fixed 5-way 5-shot episodes and frozen ImageNet encoders, and compared cosine and Euclidean scoring as paired differences on the same episodes with 95% confidence intervals. The method itself is the original prototypical-network approach. My work is the inference system around it: configuration, replaceable backends, stream boundaries, Docker and CI.

IgniteTech 2025–26

An agent that checks business rules instead of guessing them

I built an AI agent with Claude and MCP, and the most interesting part wasn’t the model - it was how we structured domain knowledge. We converted business rules from documentation into a machine-readable schema: required fields, validation logic, routing criteria and acceptable values, all explicitly defined in a format the agent can query and check against. This isn’t RAG or vector search - it’s structured data the agent can reason over. It was built and deployed in a few days and handles real service requests.

If the rules exist only in documentation, the agent is guessing. If they’re structured data, the agent knows.

Real-time

NextBridge 2024–25

WebRTC control for a smart wheelchair

I built the end-to-end WebRTC control stack: a signalling server (SDP offer/answer, ICE negotiation), a joystick-driven sender, and a Jetson-based ROS 2 receiver deployed on the chair. Since someone is sitting in it, connection resilience mattered most. There is heartbeat and timeout detection, exponential-backoff reconnection, and a safety watchdog that force-stops the chair on link loss. I also instrumented round-trip latency across the live link for continuous tuning, and streamed the on-device camera feed into the control loop as groundwork for vision-based navigation.

WebRTC · ROS 2 · NVIDIA Jetson · Python

Computer vision

Brick & Mortar AI 2025

Multi-camera tracking and re-identification

The pipeline runs YOLOv8/v11 segmentation, computes 512-d ReID embeddings from segmented person pixels only, then associates people across cameras. This cut identity switches by 20% compared with the full-bounding-box baseline. I took it to production: PyTorch to ONNX to TensorRT, the Triton configuration, a custom Triton ReID backend with a re-tuned matching threshold, and fixes for the shape-mismatch and runner-registration failures in the deployed stack. GPU-accelerated RTSP decoding raised throughput 10–15× over naive full-resolution decoding.
