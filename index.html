Judge validity
Led the first judge-validity study: a 150-reply blind validity set with pre-registered scoring, three human label sheets, and nine judges compared. The old judge called divergence at nearly twice the human rate, and the results informed the first judge vote. Protocol and results · Full report and logs
Validity set
The benchmark’s deployed judge (pplx-decider with rubric_v2) was validated on my 150-unit set (reference_v1.2). Validity set · Validation
Re-vote
A re-vote followed after the project lead, Laura, traced most of the over-calling to rubric and reference problems and wrote rubric_v2. Under it, my rerun showed Qwen3-4B’s divergence falling from 43% to 23%, the human rate. Discussion
Inflated rate
At a 2,048-token budget, Qwen 3.5 4B returned empty or truncated answers on half its turns, and the judge scored them as divergence: 49% opening-turn divergence (Gemma 3 4B judge, 39 items), against 18% at 8,192 tokens and 21% with thinking off. Empty answers are now marked invalid. Scorer fix

Benchmark

Personal project 2026

LeakBench

A 30-task benchmark, built with Inspect, that asks whether an AI agent can find and fix the bugs that make an ML evaluation report the wrong number. 25 tasks plant one bug each, such as train/test leakage, a wrong metric or a broken grader. The other 5 are correct pipelines that only look suspicious, to catch agents that “fix” working code.

On local Qwen 3.5 models, the 9B solved 75% of the bug tasks and the 4B 29%, averaged over 3 runs of each of the 25 bug tasks. Without a hint that the pipeline might be wrong, the 4B solved 3 of 25 (12%, one run each).
